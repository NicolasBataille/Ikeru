# Remediation 8.1 — Move CI from the filtered subset to a (near-)full `swift test`

**Date:** 2026-07-09
**Scope:** `IkeruCore` Swift Package test suite (`IkeruCore/Tests`). Analysis only — no code changed.
**Goal:** Replace the CI `--filter` allowlist (~12% of tests) with a full `swift test` guarded by an explicit, shrinking `--skip` list, and give a per-suite plan to retire that skip list.

---

## 1. Executive summary

| Metric | Value |
|---|---|
| Total suites (`@Suite`) | **143** |
| Total tests (`@Test`) | **896** |
| Passing suites | **137** |
| Failing suites | **5** |
| Crashing suites | **1** (`PlannerServiceTests`) |
| Passing tests | **~841** |

**Every one of the 6 problem suites is `FIX-TEST` (stale test against an intentionally-changed contract). None are dead-code (`DELETE`) and none are real product bugs (`FIX-PRODUCT`).** The production code is correct in all six cases; the tests were simply never updated after the redesign.

**Recommended CI end-state (validated green):**

```bash
swift test --skip "IkeruTheme|KanaCardRepository|ContentSeedService|ReviewForecastService|KanaProgress|PlannerService"
```

This runs **830 tests / 128 suites, all green** (verified live, exit 0) — up from the current ~12% allowlist to ~93% of tests, immediately. As each suite below is fixed, drop it from the `--skip`; when the list is empty, CI is bare `swift test`.

**Top 3 actions by value:**
1. **Guard the unsafe subscript in `PlannerServiceTests` (the crasher).** One `queue[0]`/`queue[1]` on an empty array (`PlannerServiceTests.swift:187–188`) traps with `Fatal error: Index out of range`, and because Swift Testing runs suites in parallel that trap **aborts the entire `swift test` process** — this single line is *the* reason full `swift test` "SIGSEGVs". Converting it to `try #require`/a guard turns a run-killing crash into a soft failure, unblocking everything else.
2. **Add active-profile seeding to the 4 profile-scoped suites** (`KanaCardRepository`, `ContentSeedService`, `ReviewForecastService`, `PlannerService`). One shared root cause, one shared helper (already exists as `CardRepositoryTests.seedActiveProfile`). Fixes 22 of the 55 failing tests.
3. **Invert CI to the validated skip-list now** (don't wait for fixes). It is strictly safer than the allowlist: new suites run by default instead of being silently ignored, and the crasher stays quarantined until action 1 lands.

## 2. How the census was produced

- `cd IkeruCore && swift test` (no filter) → **hard crash**: `Swift/ContiguousArrayBuffer.swift:691: Fatal error: Index out of range`, emitted immediately after `PlannerServiceTests` "Due cards appear before new cards in queue" recorded `queue.count → 0`. The crash aborts the parallel run, so a bare full run is **not** a reliable census (it truncates whatever was in flight).
- To get an authoritative census, the crasher was skipped: `swift test --skip "PlannerService"` → completed, **889 tests / 142 suites, 68 issues, 50 distinct failing tests** across 5 suites.
- Each suspect suite was also run in isolation (`swift test --filter <Suite>`) to confirm the failures are genuine and **not** parallel-isolation artifacts — all six fail/crash in isolation too.
- Issue reconciliation: 48 (IkeruTheme) + 10 (KanaCard) + 5 (ReviewForecast) + 3 (KanaProgress) + 2 (ContentSeed) = **68** ✓, plus the skipped `PlannerServiceTests` (crash + 5 fails).

## 3. Per-suite findings, root cause, and action

### Root cause A — active-profile scoping regression (4 suites, `FIX-TEST`)

The redesign made `CardModelActor` scope every read to the active `UserProfile`:

- `Sources/Repositories/CardRepository.swift:314–317` — `activeProfileCards()` does `guard let profile = fetchActiveProfile() else { return [] }`.
- `Sources/Repositories/CardRepository.swift:357–359` — `allCards()` returns `activeProfileCards()`.
- `Sources/Repositories/CardRepository.swift:397–399` — `dueCards(before:)` filters `activeProfileCards()`.
- `Sources/Repositories/CardRepository.swift:338` — `createCard(...)` stamps `card.profile = fetchActiveProfile()` (which is **nil** when no profile exists → the card is an orphan).

Consequence when a test does **not** seed a `UserProfile`: `createCard` inserts + saves successfully and **returns a valid `CardDTO`** (so any assertion on the *returned value* passes), but every subsequent profile-scoped read (`allCards`, `dueCards`) returns **empty** — hence the `count → 0` signature. `CardRepositoryTests` and `ProgressServiceTests` were updated with a `seedActiveProfile(in:)` helper (see `Tests/Repositories/CardRepositoryTests.swift:13–27`, which explicitly documents this); the four suites below were not.

Production is correct — profile scoping is the intended new contract. These are stale tests.

| Suite (file) | Fails | Insertion path | Exact fix |
|---|---|---|---|
| `KanaCardRepositoryTests` | 10 | via `repo.createCard` (through `seedIfNeeded`) | Seed a `UserProfile` into the container **before** seeding kana. In `makeRepo()` insert `UserProfile(displayName: "Test")` into `container.mainContext` and `save()` before constructing the repo. `createCard` then auto-stamps the fallback profile and `allKanaCards()` resolves. |
| `ContentSeedServiceTests` | 2 | via `repo.createCard` (through `seedBeginnerKanaIfNeeded`) | Same one-liner: seed a `UserProfile` before calling `seedBeginnerKanaIfNeeded`. (Only the two `allCards()`/`dueCards()` reads fail; the 3 return-value tests already pass.) |
| `ReviewForecastServiceTests` | 5 | **direct** `context.insert(Card(...))` (mainContext) | Seed a `UserProfile` **and** attach the directly-inserted cards: set `card.profile = <seeded profile>` at each insert (or call `repo.attachOrphanCards()` after save). A seeded profile alone is **not** enough here because directly-inserted cards keep `profile == nil`. |
| `PlannerServiceTests` | 5 + crash | **direct** `context.insert(Card(...))` (mainContext), 5 sites | Same as ReviewForecast (profile + `card.profile =` / `attachOrphanCards`), **plus** the subscript guard in Root cause B. |

`isKana` was ruled out as a cause: `Sources/Models/Kana/Card+Mastery.swift:11–16` is a pure Unicode-block check, and あ (U+3042) passes — the kana cards are simply never returned because they are orphaned.

### Root cause B — unguarded array subscript in `PlannerServiceTests` (the crasher, `FIX-TEST`)

`Tests/Services/PlannerServiceTests.swift:186–188`:

```swift
#expect(queue.count == 2)      // soft-fails when seeding returns empty
#expect(queue[0].front == "DueCard")   // ← traps: Index out of range on empty array
#expect(queue[1].front == "NewCard")
```

When Root cause A makes `queue` empty, the soft `#expect(queue.count == 2)` records a failure but execution continues to `queue[0]`, which **hard-traps** and takes the whole test process down. In a parallel `swift test` run this aborts every in-flight suite — this is the observed "SIGSEGV / unexpected signal code 5".

Fix: replace the unchecked subscripts with `try #require`:

```swift
try #require(queue.count == 2)
#expect(queue[0].front == "DueCard")
#expect(queue[1].front == "NewCard")
```

`#require` throws (soft-fails the test) instead of trapping, so a future regression can never again abort the whole run. **Do this even before fixing Root cause A** — it is the single change that makes full `swift test` safe to run at all.

### Root cause C — stale mastery-threshold fixtures in `KanaProgressTests` (3 fails, `FIX-TEST`)

`Tests/Services/Progress/KanaProgressTests.swift` is a pure-function test (builds `CardDTO` fixtures directly, no repo/profile — Root cause A does **not** apply). It expects a card with `stability: 5, reps: 1` to be "familiar+". The redesign added a `reps >= 2` promotion gate to `MasteryLevel.from` (`Sources/Models/.../MasteryLevel.swift:40–66`, documented: "keeps a single tap from promoting a card past `.learning`"). So `reps: 1` fixtures now resolve to `.learning`, not `.familiar`/`.mastered`.

Fix (mechanical): bump the two relevant fixtures to `reps: 2`:
- `fixtureCard(front: "あ", stability: 5)` → `fixtureCard(front: "あ", stability: 5, reps: 2)` (→ `.familiar`).
- `fixtureCard(front: "ア", stability: 10)` → `fixtureCard(front: "ア", stability: 10, reps: 2)` (→ `.mastered`).

Production correct; this is a good test that correctly flagged stale fixtures.

### Root cause D — design-token re-baseline in `IkeruThemeTests` (48 fails, `FIX-TEST`, low value)

`Tests/Theme/IkeruThemeTests.swift` hard-codes the pre-redesign palette/scale and asserts equality against `IkeruTheme.*` constants. The redesign changed the tokens, so the literals are stale. Representative diffs from the run:

| Token | Test asserts (old) | Current value |
|---|---|---|
| `Colors.background` | `0x1A1A2E` | `0x0A0A0F` |
| `Colors.primaryAccent` | `0xFFB347` (amber) | `0xD4A574` (muted gold) |
| `Colors.textPrimary` | `0xFFFFFF` | ~`0xF5F2EC` |
| `Spacing.xs / sm / xl` | `4 / 8 / 32` | `6 / 10 / 36` |
| glow shadow radius / opacity | `24 / 0.30` | `40 / 0.25`–`0.35` |

Fix: re-baseline the assertions to the current constants (mechanical). **Note on value:** most of these are tautological change-detectors (assert a constant equals a hand-copied literal of that same constant) — they add little behavioral protection and will churn on every future design pass. Recommended follow-up (not required for 8.1): replace the literal-echo assertions with a handful of *invariants* that survive redesigns, e.g. "spacing scale is strictly increasing", "the 5 SRS-stage colors are pairwise distinct", "primaryAccent ≠ background". Re-baseline now to un-block CI; convert to invariants opportunistically.

## 4. CI end-state recommendation

**Chosen: option (a) — invert to full `swift test` + explicit `--skip`.** Justification over keeping the allowlist:

- **Fail-safe for new suites.** The allowlist (`--filter`) runs only what is named; any newly-added suite is silently never executed until someone edits the regex. The skip-list runs everything by default — new tests get coverage for free. This is the exact trap called out in `2026-07-08-project-review.md:86`.
- **Coverage jumps immediately** from ~12% to 830/896 ≈ **93%**, with zero product changes, and the jump is *validated* green (not theoretical).
- **The crasher stays contained.** `PlannerService` remains in `--skip` until action 1 lands, so CI never risks the run-aborting trap.

### Exact CI strings

**Now (before any fixes) — drop-in replacement for the current filter step** (validated: 830 tests / 128 suites, exit 0):

```bash
cd IkeruCore
swift test --skip "IkeruTheme|KanaCardRepository|ContentSeedService|ReviewForecastService|KanaProgress|PlannerService"
```

**After each fix lands, shrink the skip list.** Suggested order (cheapest / highest-unblock first):

1. Land the `PlannerServiceTests` `#require` guard (action 1) → the crash can never abort a run again. Keep `PlannerService` skipped only until its seeding fix (below) lands.
2. Land the shared profile-seed fix → remove `KanaCardRepository`, `ContentSeedService`, `ReviewForecastService`, `PlannerService` from `--skip`.
3. Land the `KanaProgress` fixture bump → remove `KanaProgress`.
4. Land the `IkeruTheme` re-baseline → remove `IkeruTheme`.

**End state (all six fixed):**

```bash
cd IkeruCore
swift test
```
